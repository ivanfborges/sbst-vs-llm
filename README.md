# EvoSuite vs LLM-assisted tests: one Java case study

[Português](README.pt-BR.md) · [Archived academic README](docs/ACADEMIC-ORIGINAL.pt-BR.md)

A practical study for a postgraduate software engineering assignment. Two test
suites exercise the **same** `TriangleClassifier` Java class: one generated by
EvoSuite and one drafted with an LLM and subsequently refined using PIT mutation
feedback. The target class is byte-identical in both Maven projects.

**Observed in the archived run:** both suites covered 17/18 JaCoCo branches.
EvoSuite killed 16/25 PIT mutants; the refined LLM suite killed 22/25. These
are outcomes of **one target and one recorded run per arm**, not evidence that
one generation method generally outperforms the other. The LLM arm received
additional mutation-guided iteration. The academic report names **ChatGPT 5.2 Thinking**, but session settings,
model access details and human editing effort are not recorded sufficiently to
reproduce generation or compare its cost.

## Verify the existing evidence

Python 3.11 or later, standard library only:

```sh
python scripts/audit_archive.py
```

The script reads the committed archives. It checks LF-normalized hashes across operating systems, reads Surefire,
JaCoCo and PIT totals from both arms, and verifies
the archived PIT log's test-execution count against its XML. It does not run
Java, EvoSuite, an LLM, or a new experiment. Compare its output with
`docs/archive-audit.json`.

The project contains two Maven subprojects and historical logs. To check that
the **current** tests compile and pass locally, use Java 11 and Maven:

```sh
cd evosuite && mvn test
cd ../llm && mvn test
```

Those commands produce new local build files; they do not recreate the original
EvoSuite search or LLM prompts. See [results](docs/RESULTS.md) before interpreting
new coverage or mutation runs. Original dependencies are specified in each
`pom.xml`; no new version lock was introduced here.
